Platform architecture

Automation without a monolith.

Each responsibility has a clean boundary, so the planner stays platform-neutral while adapters handle network-specific behavior.

✦

AI provider

Provider interface for generated content, with a deterministic local stub for development and tests.

✓

Moderation

Brand rules, prohibited topics, required disclosures and content validation run before publishing.

◎

Human approval

AI creates drafts; a human explicitly approves the final content before live publishing.

↗

Platform adapters

Meta first, with contract for LinkedIn, X, TikTok and YouTube integrations.

◷

Scheduling

GitHub Actions supports scheduled planning and QA; production publishing can use a durable job runner.

↻

Analytics feedback

Normalized performance metrics feed future topic scoring and content planning.

Safety by default

Automation with control built in.

Live publishing is deliberately constrained until platform permissions and API behavior are validated.

Dry-run first

Development and scheduled QA use DRY_RUN=true. The Meta adapter does not send live requests in dry-run mode.

Secrets stay out of source

OAuth tokens, API keys and refresh tokens belong in environment variables and GitHub Secrets—not config files or commits.

Moderation before publish

A failed policy check blocks publication. Empty content and missing required disclosures are rejected.

Explicit approval

The publishing service requires a human approval signal before a live publish operation can proceed.

Build sequence

Start focused. Expand behind adapters.

Phase 1: Meta / Instagram + Facebook Page — completed
Phase 2: LinkedIn + X — multi-platform text/post expansion
Phase 3: TikTok + YouTube — video content and short/long-form
Phase 4: analytics-driven recommendation loop — performance scoring and topic prioritization
